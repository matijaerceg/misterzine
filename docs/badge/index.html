Some arcade cores are built the hard way: a real board on the bench, its schematics spread out beside it, a logic analyzer clipped to the pins. Hardware Verified is the release tracker's seal for that work. It marks a core whose author built it and checked it against the real hardware, and says so in public.

"Verified" means the core was built and checked against the real board or its schematics, not that every behavior was tested; absence of the badge means nothing.

See every Hardware Verified game in the release tracker

What earns it

The author went to the source, beyond MAME's code, gameplay videos and the ROMs on their own. Any one of these, in the author's own words, is enough:

  • they own or borrowed the original board and used it to build or check the core,
  • they dumped the board's PALs, PROMs or other chips themselves,
  • they worked from the manufacturer's original schematics,
  • they took logic analyzer or oscilloscope captures from a working board,
  • they published a write-up of how the logic was worked out from the hardware.

Where the core started does not matter. A core that began from MAME's documentation earns the seal once its author checks it against a board.

What it does not mean

  • It is not a score and not a promise of perfection. A Hardware Verified core can still have bugs, and the seal does not claim every behavior was tested.
  • It does not rank cores. An unbadged core is not worse, less accurate or less loved.
  • No badge means nothing at all. Many fine cores are built exactly this way and simply have no entry yet: the core is new, nobody has proposed it, or the author never wrote the work down.

The seal only ever says something good. It is never taken away as a judgement; an entry is only corrected if its evidence turns out to be wrong.

What counts as evidence

The author's own public words: the core's README or documentation, release notes, the author's blog, site or public posts. Claims made by other people about a core do not count, however likely they are. Every entry carries a short reason and the links it rests on, so anyone can check it; open a badged game's detail panel in the release tracker to read them.

How entries are made

Entries are curated by hand and each proposal is reviewed against its links before it is added. A seal sits on one game's entry: the board the evidence covers. When one core runs many games, the evidence decides which of them it reaches, so more entries can follow as more work is documented.

Propose one

Know a core that deserves it, or wrote one yourself? Open a proposal on GitHub with the game, the core and where it comes from, the links to the author's own words, and a sentence on what they show. Authors proposing their own cores are very welcome.

For developers

The full list is published as releases/badges.json, under the same catalogue licence as the rest of the release data. Each entry names its game three ways: the tracker's entry key (k, the same key as #k deep links and data.json), the shipped core file name without its date (rbfs) and the MAME set name (setnames), with the reason, the evidence links and the date it was granted.
