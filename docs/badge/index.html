Hardware Verified means the core was built and checked against the real board or its schematics; it does not claim that every behavior was tested, and absence of the badge means nothing.

Trial: Hardware Verified is a trial feature. It may change or be removed.

The seal appears in the release tracker on arcade games with public, checkable evidence that the core was built or checked against the original hardware. Each entry gives the reason and links to that evidence in the game's detail panel, and covers the games that run on the hardware the evidence describes.

See every Hardware Verified game in the release tracker

What earns it

The core was built or checked using the original hardware or its documentation, not only MAME's code, gameplay videos or the ROMs. Any one of these is enough:

  • an original board, owned, borrowed or lent to them, was used to build or check the core, including timing measurements,
  • the board's PALs, PROMs or other chips were dumped for it,
  • custom chips, PALs or PROMs were decapped, photographed or analyzed, and the core's logic derived from that,
  • it was built from the manufacturer's original schematics,
  • captures or recordings from a working board were compared against the core, with the differences documented,
  • a write-up shows how the logic was worked out from the hardware,
  • it runs on identical hardware to a game that has already earned the seal.

Games that run on identical hardware inherit the seal once one of them earns it. Identical means the same board and custom chips, not a similar one.

Where the core started does not matter. A core that began from MAME's documentation qualifies once it has been checked against a board.

The use of AI tools in a core's development is irrelevant in itself. What matters is verification against real hardware, as evidence that accuracy to the original experience was paramount in the development process.

What it does not mean

  • It is not a score and not a promise of perfection. A Hardware Verified core can still have bugs, and the seal does not claim every behavior was tested.
  • It does not rank cores. A core without the seal is not worse or less accurate.
  • Absence of the seal means nothing. A core can have no entry because it is new, or because the hardware work behind it has not been documented in public.

An entry is never removed as a judgement; it is corrected only if its evidence turns out to be wrong.

What counts as evidence

Evidence can come from anyone, not only the core's author. The community is small, and board owners, schematic holders and testers often contribute alongside developers. What matters is that the evidence cites something factual and checkable: a named board in someone's hands, a schematic set, a dump, a capture, a comparison write-up, or a post describing the work. A bare assertion that a core is accurate is not evidence; a citation of concrete work is, and gets the benefit of the doubt.

For developers

The full list is published as releases/badges.json, under the same catalogue licence as the rest of the release data. Each entry names its game three ways: the tracker's entry key (k, the same key as #k deep links and data.json), the shipped core file name without its date (rbfs) and the MAME set name (setnames), with the reason, the evidence links and the date it was granted.
